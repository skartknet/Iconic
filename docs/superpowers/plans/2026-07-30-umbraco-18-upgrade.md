# Umbraco 18 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `UmbracoV18` test site to the Iconic solution and verify the Iconic package works against Umbraco CMS 18.

**Architecture:** Clone the existing `UmbracoV17` test-site project as `UmbracoV18`, bump its Umbraco.Cms package reference to 18.0.2, wire it into `Iconic.sln`, bump the shared `Our.Iconic`/`Our.Iconic.Core` package versions and the frontend's `@umbraco-cms/backoffice` dev dependency, rebuild the TS bundle, then manually verify the Iconic property editor in the new site's backoffice.

**Tech Stack:** .NET 10 / ASP.NET Core, Umbraco CMS 18.0.2, TypeScript + Lit + Vite, npm.

## Global Constraints

- `UmbracoV18` targets `net10.0` (same TFM as `UmbracoV17` — Umbraco.Cms 18.0.2 requires `net10.0`).
- `Umbraco.Cms.Core` PackageReference in `Our.Iconic.csproj` / `Our.Iconic.Core.csproj` stays at its existing floor (`16.0.0`) — do not bump it.
- `Our.Iconic` package version → `18.0.0`; `Our.Iconic.Core` package version → `18.0.0`.
- `@umbraco-cms/backoffice` devDependency → `^18.0.2`; `Our.Iconic/package.json` `version` → `18.0.0`.
- No source-code changes to `.ts`/`.element.ts` files or to `Our.Iconic.Core`'s C# classes are expected — if verification reveals an actual incompatibility, fix it in place rather than deferring.
- New site's SQLite connection string file must be uniquely named (`Umbraco_v18.sqlite.db`) so it doesn't collide with other test sites.
- New site's launch ports must not collide with `UmbracoV16` (`51693`/`44323`) or `UmbracoV17` (`26290`/`44378`). Use `27291` (HTTP) / `44490` (HTTPS).

```xml
  <PropertyGroup>
    <!-- Razor files are needed for the backoffice to work correctly -->

```

**Interfaces:**

- Produces: confirmation that Iconic works end-to-end on Umbraco 18, closing out this plan.

- [ ] **Step 1: Run the site**

Run: `dotnet run --project UmbracoV18/UmbracoV18.csproj`

In the backoffice: Settings → Document Types → create (or edit the existing

be assigned to a property without error.

- [ ] **Step 4: Configure a package and pick an icon**

On the Iconic data type's configuration screen, add a new package (custom
CSS + selector regex, or one of the bundled preconfigurations), save it,
then go to a content node using that document type and open the icon
picker. Select an icon.
Expected: the modal opens, icons render (styled via the loaded CSS), and
selecting one populates the property value.

- [ ] **Step 5: Save and reload the content node**

Save and publish the content node, then reload the page.
Expected: the document does **not** show "Discard unsaved changes" on
navigating away immediately after a fresh load (i.e., the persisted value
round-trips cleanly), and the previously selected icon still displays.
